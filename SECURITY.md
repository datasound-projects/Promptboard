# Security

Promptboard is a local, single-user app. It starts AI coding agents that can edit files in your repositories, so read this before you use it with sensitive code.

## Reporting a vulnerability

Report problems privately through GitHub: **Security → Report a vulnerability** on this repository. Do not open a public issue, and do not attach credentials, private code, or prompt history.

## What the app does to protect you

**Local only.** The server binds to `127.0.0.1` and checks the Host, Origin, and fetch-site headers. Every API request needs a per-process token, sent in a header and never in a URL. An app restart makes a new token; a page whose request is refused for that reason reads the session again and sends the request once more. Pages use a strict content security policy with no inline scripts or styles. Do not expose the port through a proxy or tunnel; the local app refuses requests that carry proxy headers.

**Remote access is opt-in and paired.** Off by default. When you turn it on for Tailscale or Twingate, a second listener starts on 127.0.0.1 or a private address of this computer (never a public or wildcard address) and every request on it needs a paired device: a one-time code (valid 10 minutes, used once, eight wrong tries void it, and after five wrong codes in a minute pairing waits a minute) gives the phone an HttpOnly SameSite=Strict cookie stored only as a hash, revocable at once, including its open streams. The listener checks its own Host allowlist and that Origin matches Host, and refuses Tailscale Funnel requests; Promptboard never turns Funnel on or changes Tailscale or Twingate settings except the Tailscale Serve command you confirm. A paired device has the same control as you at the computer; changing remote access, sign-ins, native dialogs, opening windows on the computer and Base imports stay local. See [remote access](docs/remote-access.md).

**Agent workspace and permissions.** Each task gets its own Git worktree and branch outside your checkout. Legacy Planning and Code Review, and typed Planning and Code Review columns, use each CLI's read-only mode (Claude Code plan mode with read tools only, Codex `--sandbox read-only` without approval prompts, Gemini plan mode plus a deny policy); no setting can make them writable. Writing stages ask by default: Claude Code `acceptEdits` and Gemini `auto_edit` accept file edits and ask for other actions; Codex uses `--sandbox workspace-write --ask-for-approval on-request`. Autonomous modes exist only when you choose them in the board's or a column's execution permissions: autonomous workspace access maps to Claude Code `auto` (its own classifier approves or refuses each action without a prompt; Claude has no workspace sandbox), Codex `--sandbox workspace-write --ask-for-approval never`, and Gemini `yolo` inside `--sandbox`; full access maps to Claude `bypassPermissions`, Codex `danger-full-access` and Gemini `yolo` without a sandbox, and should be used only on a machine or container you can afford to lose. The policy is resolved in one function and translated in one adapter table (src/pipeline-config.mjs, src/agents.mjs); a column's raw permission mode can never select a bypass. Promptboard never pre-trusts a folder or edits a CLI's trust settings, and never presses Enter on a timer. Only with the opt-in Workspace trust setting does it answer a CLI's folder-trust menu, and only when the rendered screen is positively identified as that provider's menu naming the card's own task worktree (src/workspace-trust.mjs); the CLI then records that decision itself. Selected Base MCP definitions use generated per-run configuration outside the worktree; global CLI configuration, credentials, provider home directories, and tracked project instruction files are not changed.

**You confirm the important steps.** Runs start only when you start them or turn on automatic start for a column. On legacy boards, a stage succeeds only when you confirm it. Promptboard commits only when you confirm a commit, move or complete a stage (typed columns make a checkpoint commit when a stage completes, which happens without a prompt when the column's completion is automatic), or run Autopilot. Branch updates need confirmation. Merges need confirmation unless you turn on **Merge automatically** (legacy boards) or automatic completion for a typed Merge column; even then Promptboard merges only when the accepted review and passing tests belong to exactly the current task and target commits. The target branch only moves forward: column pipelines first squash the task into one commit on top of it (the default merge method), legacy boards fast-forward. The only push is **Open pull request**: after you confirm, the task branch (never another branch) is pushed without `--force` and a pull request is opened with the GitHub CLI; its description is yours, and the task prompt is not sent unless you add it. Testing and Merge agents write only in the task worktree; they are told not to commit, merge, rebase, reset, or push, and Promptboard refuses to commit files that still contain conflict markers. Git is set up in a folder (`git init` plus one empty commit) only when you create a project, open a folder that is not a repository yet, or confirm **Set up Git here**; it never adds your files. Promptboard never force-resets, stashes, or deletes a dirty worktree.

**Autopilot is opt-in per project.** Starting it needs an explicit acknowledgment, because it then confirms finished agent turns, commits, accepts reviews with no issues, and merges (through the same gate as a manual merge) or pushes the task branch for a pull request without asking each time. It advances only when an agent has finished its turn, never while an agent waits for permission, and it pauses on anything unexpected. A scheduled card goes to Autopilot only when you switched on **Run with Autopilot** for its schedule and confirmed it; a paused Autopilot is never resumed for it, and schedules restored from a backup come back switched off.

**Opt-in column pipelines.** Pipeline permission modes are explicit configuration, independent of stage names. Native plan mode permits the CLI approval flow instead of the legacy plan-exit denial. Codex plan sessions use read-only/on-request. User CLI tools and selected Base resources remain available subject to CLI permissions. Moves between custom (untyped) columns supply no hidden stage instructions and perform no commit, test, review, or merge action; typed stage columns (the default for new projects) do, as described in [Kanban execution](docs/kanban-execution.md). An agent can perform whatever the configured CLI permissions and user prompts permit. Compatible moves preserve the process; Done suspends/archives, and To Do stops/resets the current session reference while keeping files. Native restoration rechecks selected Base resources, repeats no task text, and supplies changed Base text only when definitions changed. Pipeline input rejects terminal control characters before argv/paste delivery, without modifying stored task text. Configured scripts/webhooks use durable move/action grants, verified workspaces, scoped cancellation and no-replay recovery. Scripts deliberately execute user-configured shell code; task text is supplied through literal environment values and stripped template substitutions. Enabled deferred "on enter" message rows run through the native message scheduler; immediate and exit message rows and advanced session strategies are refused. Version 6 migration preserves existing pipelines, legacy behavior and logical sessions; importing pipeline backups disables dispatch.

**Processes are owned.** Stopping a run, or Promptboard itself, stops only the processes it started: agent and CLI process groups, test commands, live previews, MCP servers and a folder picker that is still open.

**Credentials stay with the CLI.** Promptboard never reads, copies, or logs CLI credential files, and does not copy them into worktrees. In Docker mode, Codex's own sign-in file is mounted read-only into the card's container (never copied), and Claude Code uses a token you create with `claude setup-token` and paste in Settings: it is kept in the data folder with owner-only permissions, passed to the container by variable name only, and never written to `state.json`, a backup, a log, an API reply or a command line.

**Docker mode is opt-in per project.** With **Run agents in Docker** on, each card agent (Claude Code or Codex) runs in a container that mounts only the card's worktree (its `.git` pointer read-only), the repository's Git data read-only except its objects and that worktree's own Git folder (whose `commondir`, `gitdir`, `HEAD` and `config.worktree` stay read-only, so nothing the agent writes can make Git on this computer read settings or hooks from elsewhere; branches are read-only, so the agent can stage but not commit), the run's folder, and Promptboard's code read-only, spelled as on this computer. A Git repository the agent makes inside its worktree would run its own settings (fsmonitor, filters) in any Git command there, so for such a card Promptboard lists those repositories without running anything in them and refuses its own Git work until you delete them (`NESTED_REPOSITORY`); do not run Git there yourself before then. Planning and Code Review get the worktree and Git data read-only, enforced by the container. Codex's own sandbox cannot start inside a container (bubblewrap needs user namespaces that Docker blocks), so there Codex runs with `--sandbox danger-full-access` and the container is the boundary; Promptboard never loosens the container's security profile and never uses `--dangerously-*` flags. Every run first checks Docker, the image, the sign-in and that the folders are really shared; any failure ends the start, never with a fallback to the host. Stop, Pause and shutdown remove the container, and startup removes containers a crash left behind. Docker mode does not isolate the network (the CLIs need their APIs), files in the worktree that later run on this computer (test commands, scripts, code you merge), the writable Git objects and index, or the sign-in the agent runs with. See [Docker sandbox](docs/docker-sandbox.md).

**Project memory sends one short summary after each merge.** When a card is merged (or its pull request is merged on GitHub) and the project's **Suggest lessons after each merged card** switch is on (the default, in Kanban project settings → Memory), Promptboard runs the CLI that executed the card once, with every tool disabled, in an empty temporary folder, with its smallest model (Claude Code `haiku`, Codex low effort, Gemini CLI `flash`; the owner can choose another) and a 3-minute limit. **Suggest lessons** on a merged card does the same once on your click. The CLI receives, at most about 24,000 characters: the card's number, title and text (first 3,000 characters), the executing agent's summary, the review verdict and findings, the test commands with pass or fail and the last output of failed ones, rework notes and stage-history reasons, the target branch and commit count (or the pull request number), the changed file names, and the project's approved lessons. Local folders are cut to their last name and secret-looking values are masked; environment variables, CLI credentials, transcripts and terminal logs are never sent. The answer is stored only as suggestions in `<data folder>/lessons/`; nothing reaches an agent until you approve it, and approved lessons are then added as one bounded section to every new agent run of that project. The run takes the shared one-job CLI slot and steps aside for your own CLI work; it is never retried on its own after a failure, nor after it was stopped 3 times. Failed-test output is masked in full before its last 600 characters are kept. See [Project memory](docs/project-memory.md).

**No shell interpolation of user text.** CLIs, Git, and your test commands start through `execFile`/`spawn` without a shell. Task text is passed as one argument or pasted into the terminal, never interpolated into a command. Kanban provider executables and flags remain adapter-controlled. A Base stdio MCP definition is an explicit exception for the program and argument list: it is user-configured, must be trusted, and can execute only through an explicit connection test or an authorized agent run. A command recipe is instruction text for the existing CLI, not a separate tool executor.

**Workspace editing is explicit and folder-scoped.** File trees use the selected project folder even inside a parent repository. Inspection starts no agents. Save requires the current content hash and canonical folder identity, revalidates project/worktree custody, refuses links/credentials/binary or oversized files and serializes competing app saves. Atomic replacement retains ordinary permissions; external editors do not share the app's lock. Unsaved drafts remain in memory, are not overwritten by refresh, and require explicit discard on close. The optional AI panel sends only the selected file/draft and request through the existing tool-disabled provider in an isolated temporary directory; it creates no Kanban task or workspace. A bounded validated proposal must be reviewed/applied and explicitly saved. Cancellation rejects late proposals. CLI policy limitations still apply; see [workspace file boundaries](docs/workspace-files.md). The [project explorer](docs/project-explorer.md) can also create an empty file or folder, with the same path checks and folder identity and an exclusive create that never replaces an existing name; its Git status read is read-only and takes no optional locks.

**Initial terminal input has one owned attempt.** Long initial envelopes use the existing bracketed paste and delayed Enter, only after the CLI's own readiness sign (main SessionStart; Codex's first terminal title) and never on a timer alone, so a startup question such as folder trust cannot take them as its answer. Changed human input, process ownership or native identity revoke Enter without clearing a draft. Stop/Pause/exit clear owned timers. Unknown transport outcomes stay uncertain and cannot trigger a retry, recovery restart or raw error publication. Receipt checkpoints cannot use pending submission as confirmation; automated continuation scheduling remains separate.

**Enter-message handoff is not native delivery.** The optional coordinator callback must persist the exact rendered message hash, mode and provider/session/run tuple before acknowledgement. Placement cannot invent queue acceptance or conversation confirmation. Unknown saved outcomes block the group without replay; the caller owns cancellation and native readiness. The board connects enabled deferred enter rows through the owned scheduler and native transport. Preparation and actual input remain bounded separately from cancellable queued/busy readiness waits. Cached readiness grants no input; native dispatch repeats current process, lifecycle and terminal checks before writing. Manual input and uncertain outcomes retain their guards. No path clears a human draft or retries unknown input.

**Deferred column-message recovery.** State version 8 retains bounded task-scoped pending references independently of visible history; migration keeps exact original bytes and portable backups omit these process grants. Startup marks dead-owner deliveries interrupted without sending input. Stop, content edits, To Do/Done and shutdown cancel owned requests and await bounded outcomes. Unknown saves remain blocked; missing journals cannot grant replacement input. Message confirmation proves input only, not completed work.

**Journal-backed input retains its acknowledgement boundary.** Exact tuple/hash and task preflight precede one journal dispatch grant. Native submission/acceptance and confirmation saves require strict acknowledgements; confirmation is saved while input remains owned. Unknown final acknowledgement blocks further input instead of replacing a stored receipt or replaying its message. Per-run FIFO retains earlier live tails through cancellation, and queued-only cancellation cannot overwrite a competing grant. This bridge starts no session and changes no CLI configuration. Configured deferred enter rows use it through the Board-owned scheduler. See [the bridge contract](docs/native-message-dispatch.md).

**Deferred native input is a private seam.** The caller must acknowledge an exact durable grant before bytes and persist the outcome before advancing work. Supervisor ownership, completed/settled main activity, observed paste mode and an untouched human draft are independent requirements. One attempt consumes its dispatch ID; partial/unknown writes stay uncertain and block automatic completion even after Stop. Cancellation and deadlines bound persistence/event callbacks; late acknowledgements cannot revive input. Native turns confirm exact message text only, not task completion. This path never clears drafts, presses Esc, retries, changes CLI flags or uses an unrelated shared-server queue. Configured deferred enter rows publish pending references before grants and retain uncertain outcomes without replay. Immediate/exit/slash input remains unavailable. See [the transport contract](docs/native-message-input.md).

**Exact Codex history lookup.** Per-run usage and read-only receipt custody search only bounded canonical session date folders for the observed thread. A complete bounded UTF-8 metadata header must match that exact ID; a provided source must be CLI. Descendant symlinks, malformed, ambiguous, reverted or compressed files cannot supply a substitute history. Lookup paths remain in owned process memory, outside public run updates and portable backups. This evidence does not grant terminal writes or permissions.

**Browser notification reception is opt-in.** Only the settings button requests native permission. Authenticated bounded NDJSON streams carry literal task alerts without external images or URLs; tokens remain in headers. One receiver lease and nonce own each action. A native browser display event is acknowledged once; construction, transport, missing receipts or receiver loss cannot fabricate success. Disconnect, cancellation and shutdown never replay an alert. Alert clicks select the exact project/task and perform no agent or movement action. The browser report is not proof of OS visibility or human acknowledgement.

**Board profiles and task choices are inert definitions.** Named profiles share columns, automations and Base assignments; task pins use validated native provider tuples, never commands or arbitrary CLI flags. Changed task settings require exact card/project revisions and no active run or unresolved automation. Saving never starts or signals a process or connects a tool. Profile deletion falls back to Default only in the same guarded configuration write. Portable v5 imports preserve choices with all dispatch disabled and no machine session references.

**Repository board review has fixed read custody.** Only `promptboard.json` and `promptboard.local.json` at the linked root are read, with bounded fatal UTF-8 JSON and regular single-link descriptor/path checks. Replaced roots, symlinks, hardlinks and changing files fail closed. Applying requires confirmation and exact file/project revisions, rechecks both files inside the serialized configuration write, and retains active-run/automation/occupied-column guards. It never writes repository files, changes Git ignore rules or dispatches an action. Personal profiles and arbitrary CLI flags are rejected; personal automation groups replace rather than combine with team groups. Configured executable rows are reviewed definitions for later authorized moves.

**Repository change detection is read-only.** Only a previously accepted source is monitored for the selected visible Kanban project, with bounded reads and at most one in-flight request per current project/source snapshot. Status returns opaque revisions, source presence and fixed error codes, without file content, prompts or executable definitions. It does not invoke Git or a provider, alter state/files, apply a definition, connect Base or signal a process. Invalid/missing sources keep saved settings; stale replies cannot affect a newer project/source. Portable imports do not establish this machine-specific file baseline.

**Task labels are display metadata.** Authenticated catalog and assignment edits check independent label revisions and card revisions. Bounded names and stable IDs cannot inject terminal input or configuration; colors accept only six-digit hex values. Metadata edits preserve agent settings, Base and pending message custody. Portable label imports remain inert and reject malformed or foreign assignments before publishing state.

**Base is optional context, not an authorization boundary.** Creating, enabling, importing, or assigning a resource never starts a run, installs packages, approves a command, or changes a provider. Trust, availability, assignment, connection status, and compatibility are separate. Imported resources begin inactive and untrusted. Executable definitions require explicit trust; trusting them does not weaken the agent's permission mode. Base MCPs and command recipes are unavailable in Planning and Code Review, regardless of MCP `readOnlyHint` annotations.

**Connection tests execute real protocol operations.** An explicit trusted MCP test initializes the server and discovers its supported capabilities. Stdio testing executes its configured program; local HTTP MCP endpoints can deliberately contact local services. Tests have bounded output, timeouts, cancellation, and owned-process cleanup. They never run on save, page load, import, or assignment and do not invoke discovered tools. Selecting one MCP tool supplies its parent server; it does not claim to hide other tools on that server.

**Kanban CLI tool inheritance.** Writing-stage Claude, Codex, and Gemini agents inherit tools and MCPs configured through their underlying CLI, alongside Base delivery. Claude keeps ambient MCP configuration; Gemini keeps configured extensions and MCP servers. Native permissions, trust prompts, and administrator policies still apply; Base is not an exclusive tool boundary. Planning and Code Review retain their current restrictions, and Composer adapters are unchanged. Inheritance does not read credentials, copy ignored project configuration, or edit CLI settings files. Manifests record Base-managed delivery, not every inherited tool.

**Nested agent profiles use native CLI delegation.** Claude writing-stage subagents receive bounded session-scoped JSON with pinned instructions/context. They inherit the parent permission mode; Base never passes a subagent permission override, installs an agent file, changes global settings, or creates a second scheduler. Incompatible providers/stages report omissions or block required selections. MCPs remain subject to the session’s permissions; resource selection is not a claim of tool exclusivity or observed invocation.

**Sources and secrets.** MCP environments and HTTP headers store variable names, not credential values. Resolved credentials are not placed in resource previews, prompt sections, exports, manifests, or application diagnostics. Repository context resolves in the run's task worktree. External roots need explicit approval and can be revoked; real-path, symlink, excluded-file, traversal, and size checks apply. Dependency folders, generated output, and common secret files are excluded. Public documentation requests check DNS addresses and every redirect, pin the checked address, reject private networks and credential-bearing URLs, and limit fetched text. These document rules are separate from explicitly configured MCP endpoints.

**Documents are untrusted.** Base text and wiki Markdown are rendered with safe DOM text nodes and a limited Markdown renderer; imported HTML is not inserted into the page. Selected instructions, documents, command recipes, and tool output can still influence a model. Local storage does not prevent selected context from being sent through a cloud-backed CLI. Wiki generation is optional, uses the same restricted generation job coordinator as Compose, and produces a reviewable draft. Cancellation targets its operation ID; stale updates cannot overwrite a newer wiki revision.

**Agent portraits are optional image API requests.** Only an explicit Generate action sends the avatar description to the fixed OpenAI Images HTTPS endpoint. Credentials remain in the server environment, are never collected from CLI sign-in, and are excluded from definitions, logs, exports, and errors. Responses are bounded raster PNG/JPEG content, never SVG/HTML. Saving stores image content in immutable resource revisions outside state metadata; avatar reads require the existing session token. Portraits are not supplied to coding agents. Export includes image bytes only when document content is explicitly selected. Generation uses the existing job coordinator and scoped cancellation/shutdown handling.

**Compose cancellation replaces generation deadlines.** Compose model calls wait for completion or Cancel; finite research calls/lookups, output limits and optional-source timeouts remain enforced. Cancel sends a session-protected, request-scoped message independently of browser disconnect; stale cancellations cannot stop another job. Cancel/disconnect stops owned provider work, observes late adapter failures and releases the UI job. Shutdown separately waits for actual provider cleanup before killing remaining owned processes. Codex prompt-writing calls disable inherited MCPs/apps/plugins/hooks per invocation using bounded metadata and credential-free overrides; selected Compose sources use the read-only adapter. CLI defaults and Kanban tool inheritance are unchanged.

**Origin blueprints are inert planning data.** Each project's blueprint is a separate, versioned file in the data folder's `origin/` directory; its name is derived only from the validated project ID, never from user text. Origin writes the board only through its Kanban handoff and Create Kanban project, writes Base only when you choose Save in Base or Use in Kanban for a Project Context, never writes sessions or repositories, and saving a blueprint never starts an agent, a model call or a network request. Writes are serialized, atomic, revision-checked and keep a backup; damaged files are quarantined and newer-version files are refused. All blueprint text is rendered as DOM text. Source URLs accept only http/https without credentials and open with `rel="noopener noreferrer"`; Origin does not fetch them. Blueprint links to Base resources are references by ID, read and never copied or changed. The Compose handoff only prefills the prompt field; the Kanban handoff uses the normal authenticated task API and creates To Do cards only.

**GitHub through the GitHub CLI.** Sign-in runs the official `gh auth login --web`; Promptboard reads only the one-time code that gh prints for you and declines gh's global Git credential setup. Tokens stay in gh's keychain storage and never reach the board, the browser, logs, URLs, process arguments, or Git remotes. A clone Promptboard makes lives in the data folder or in a folder you choose; for an HTTPS remote it gets `gh auth git-credential` as a credential helper in that clone's own config only. Fetch never changes a branch; updating the target branch is a confirmed fast-forward. Disconnecting a project never signs gh out.

**Usage data.** The Usage panel scans known local Claude, Codex, and Gemini session directories, including sessions outside Promptboard, for the last 30 days. It reduces structured records to numbers, model IDs, timestamps, and tool names; transcript text and tool arguments are not retained or returned. Scans are bounded, skip symlinks and oversized files, and label incomplete coverage. No credential files are read. Codex account limits use its read-only app-server method. New Promptboard Claude sessions have a per-process status-line command that saves only whitelisted usage fields to their run folder; global CLI configuration is not edited. A refresh failure never fabricates available quota or costs.

**Persistence and revocation.** Base uses Board's serialized Store. Immutable content is saved before its metadata is published. State version 2 migrates explicitly to version 3 with a retained original backup; migration errors and unknown newer versions are not treated as an empty installation. Resource and assignment revisions are independent of run polling. Accepted runs pin definition revisions; current disablement, missing resources, revoked trust, and source access revocations prevent queued delivery without substituting newer content. Revocation does not remove context already supplied to a running process. Deleting a referenced resource requires detachment; historical immutable definitions and supplied context remain in the local data directory.

**Conversation metadata and resume.** State version 4 separates logical sessions from process runs. Migration retains an exact original version 2 or 3 backup and preserves Base. Pause persists intent before signalling only the owned process. Resume requires the existing token/origin protections and explicit consent, validates the saved native ID, and uses the saved provider configuration in the same stage and workspace. Latest-session aliases, transcript paths, changed task text, active/archived tasks, and revoked Base resources cannot resume. It never repeats the original task or portable Base text; native tool delivery is prepared anew. A reported conversation-ID mismatch stops the process without overwriting the original ID. Recovery never relaunches agents. Portable board backups exclude machine-specific session references.

## Limits

- An agent in Executing can run any command its CLI allows in the task worktree, with your user's permissions. Review what it asks to do.
- Worktrees are created with Git hooks disabled. Commits you confirm run your repository's normal Git hooks, like any commit you make yourself; a squash merge is built with `git commit-tree`, which runs no commit hooks. The agent's own commands and your test commands also run normally.
- A live preview runs the project's own preview command (and its setup commands, such as `npm ci`) in the card's worktree on this computer, like test commands: with your user's permissions, not in Docker or a sandbox. It is asked to listen on `127.0.0.1` (`HOST=127.0.0.1`); a dev server that ignores this is reachable from your network, as when you start it yourself. An imported preview command waits for your confirmation. See [Live preview](docs/live-preview.md).
- These controls do not protect against other software that already runs as your user.
- Prompt boundaries and read-only modes are enforced by each CLI, not by an operating-system sandbox, unless the project runs its agents in Docker; then the container also limits what the agent can reach. A CLI bug can weaken the CLI's own limits.
- Prompt text, run output, plans, Base documents, and supplied context are stored unencrypted in the data folder and may be sent to your provider through its CLI. **Do not put API keys, tokens, passwords, or private code you cannot share with your provider into prompts, tasks, or resource documents.** Resource and board exports include document bodies only when requested; review them before sharing. Imports remap resource IDs and external-root references rather than reusing local access grants.

## Changes that need extra review

- CLI flags, permission modes, hook or notify handling, and executable lookup.
- Git worktree, commit, merge, and cleanup code.
- Process start, stop, time limits, and output limits; Docker mode mounts and container cleanup (src/sandbox.mjs).
- HTTP binding, token and origin checks, static routes, and the content security policy.
- Anything that renders agent output (it must stay text, never HTML).
- Base trust/revocation, immutable revisions, MCP configuration and discovery, source containment and network fetching, import remapping, and wiki job coordination.

Do not add automatic approval bypass, shell interpolation, remote binding, force-push, pushing without confirmation, or conflict resolution that skips the marker check and the user's commit.
