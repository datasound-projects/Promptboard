# GitHub preview caching and explicit synchronization

Saved GitHub sources open machine-local cached preview pages when available, including after restarting the app or switching projects. The picker labels snapshot check time and incremental changes-check time separately. Cached data is not a claim of current GitHub access or a complete repository catalog. Open/Closed/All and the other filters remain local to the displayed page. Unvisited or evicted pages are read from GitHub when requested. Nothing synchronizes in the background.

**Refresh page** rereads the current source page. Refreshing All page 1 discards older page positions and establishes a new incremental baseline. This explicitly recovers an oversized change history or invalid derived preview without changing sources, drafts or duplicate identities. Newer formats and filesystem access problems are refused unchanged.

**Sync changes** requires no selected issues. It reads Open and Closed changes with GitHub's `since` filter in ascending updated order, with a one-second overlap. PR-only pages still advance. Reads are bounded to 20 pages and 16 MiB of normalized changed metadata, sharing a 30-second network budget with any necessary first-page refresh. Unsupported metadata, duplicate identities across moving pages, access failures, timeouts and failed cache publication preserve previous cache bytes and cursor. There is no automatic retry. Refresh page 1 to reset an oversized change history.

Sync updates exact metadata for known cached issues while retaining labeled snapshot positions. Filtered snapshots are invalidated when metadata changes. If a changed issue is not cached, or All page 1 is missing, old pages are invalidated and page 1 is reread. No changes require only the incremental request. Snapshot positions do not promise current GitHub ordering. The change count includes valid identities in the overlap, rather than only newly created issues. GitHub pagination is not transactional and sync is not a deletion feed. Changes during a read remain eligible from the next sync's start-time cursor.

The cache stores at most 12 pages and 16 MiB per saved source in `backlog-preview-cache` under app data. Files use opaque project/source hashes and private creation permissions. Entries validate literal metadata, ownership, links, timestamps and pagination; directory/file links, nonregular files and excessive reads are refused. Writes use an exclusive temporary file, flush and atomic replacement with source ownership rechecked before publication. Reconnected sources use distinct identities. Derived snapshots stay outside portable backups and board state; state schema remains 12 and portable format 10.

Sync creates no drafts, edits no imported tasks, advances no board numbers and starts no agents. Locally edited text, duplicate identities, exact Composer/split To Do routing, Base and configured CLI tools are preserved. Import rereads the selected GitHub page and checks existing revisions before atomic publication. Unavailable or shifted selections require explicit refresh rather than importing stale descriptions.

Authenticated GET `backlog/sources/:id/preview` supports `state`, `page` and `refresh=1`. Authenticated POST `backlog/sources/:id/sync` requires `expectedImportRevision`. Both retain token/origin and pipeline ownership checks. Old servers without `pipelineBacklogSourceCache` use live previews and cannot submit the hidden sync action.

References: [GitHub Issues API](https://docs.github.com/en/rest/issues/issues#list-repository-issues), [GitHub CLI API](https://cli.github.com/manual/gh_api), [Kangentic Backlog/imports](https://www.kangentic.com/guide/backlog/). This checkpoint caches pages with explicit sync; automatic full-source synchronization is outside this task.
