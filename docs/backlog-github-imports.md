# GitHub Issues import backend

This step adds saved GitHub repository sources and selected-page issue imports to pipeline projects. The [source picker](backlog-github-import-ui.md) exposes these operations with explicit page selection. Persistent preview cache, incremental sync, attachment downloads and other tracker adapters follow separately.

Authenticated POST `backlog/sources/github-issues` accepts a repository name/HTTPS URL and `expectedImportRevision`. The existing non-interactive GitHub CLI verifies read access before the source is saved. Source removal uses DELETE `backlog/sources/:sourceId` with the same revision. A project can save 20 sources. These operations do not change board settings, Base assignments, pending messages or agent sessions.

POST `backlog/sources/:sourceId/import` accepts up to 100 selected global issue keys from one source page, optional `state` and `page`, and captured import/backlog/label revisions. The backend rereads the selected source page and publishes the entire accepted batch in one atomic state update. A vanished selection, invalid metadata, stale project ownership, insufficient capacity or failed durable write publishes no drafts, labels or identity entries. It returns created drafts and skipped duplicate identities. The existing 1,000-draft and 100-label limits apply; each draft supports 20 labels. The duplicate ledger holds at most 10,000 identities per project and reports its limit explicitly.

Descriptions retain their exact source bytes, including CRLF and whitespace. Imported drafts start with no board number, workspace, provider configuration or session. GitHub does not supply the board's priority scale, so new drafts use None. Existing labels match by normalized case-insensitive name and retain their colors/IDs; new labels use source colors. Assignees and the original title/link are preserved as display provenance, independently of generation/check metadata. Source titles longer than the board's 120-character title limit require an explicit `titleOverrides` entry; the original title remains in provenance.

Stable global issue identity survives promotion, Done archiving, card deletion, source removal and reconnection. Re-importing a known identity skips it rather than overwriting local text or recreating the task. Provenance references and the ledger are checked together. Source access grants no execution privileges, and importing starts no agents. Later promotion uses the existing arrival lifecycle and configured Base/ambient CLI inheritance.

State version 12 adds empty import catalogs/identities while preserving all version 11 backlog drafts, labels, tasks, Base and native state. Migration keeps an exact original backup, and newer versions are refused unchanged. Portable version 10 preserves source definitions, provenance and duplicate identities while retaining inert import behavior; older portable formats begin with empty import metadata. Browser migration cannot represent these fields and requires portable import instead.

The [read-only preview foundation](github-backlog-preview.md) provides source pages. Kangentic's [Backlog and imports](https://www.kangentic.com/guide/backlog/) supplies the target workflow. The picker adds inline source links and guarded selection; persistent caching and incremental synchronization remain pending.
