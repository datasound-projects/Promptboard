# Column automation runtime

Opt-in pipeline boards can now execute configured script and webhook rows through their common move path. Existing stage boards retain their behavior. Composer still inserts the exact engineered prompt or edited split task into the To Do role without an agent. Native agent configuration and selected Base delivery still use the existing Supervisor and CLI adapters.

A cross-column move records its immutable journal intent and task reference before effects. It runs the source's exit rows in order, grants and records the session lifecycle, then runs the destination's enter rows. Failed rows retain their outcomes and do not stop later rows. Cancellation and unconfirmed script termination prevent advancement. To Do and Done permit exit rows only; manual active columns run their other enter rows without starting an agent. Same-column ordering runs no automations.

Scripts use the verified registered task worktree, including its recorded repository and branch, or the verified project checkout when there is no worktree. Exit metadata is captured before asynchronous verification; task/project changes during verification or exit prevent the lifecycle. Enter metadata uses the accepted placement and workspace. Task edits during enter prevent a prepared new agent from starting. Already confirmed effects and accepted placement remain recorded rather than rolled back or repeated.

For a fresh/resumed agent, the lifecycle prepares the run and workspace, but does not queue its native startup until preceding non-message enter rows finish and the move is saved. Existing queued agents keep their FIFO place behind an opaque hold during their actions and any configuration retargeting. Later queued runs can start meanwhile; once released, the held agent starts before those still waiting. Releasing a hold requires the exact owning token; Stop cannot resurrect a cancelled queue entry. Live compatible agents remain attached throughout their actions. Agent messages remain refused until their separate native scheduler is integrated. Notification rows use [explicit browser reception and display acknowledgements](pipeline-notifications.md); absent or unconfirmed receivers report `unconfirmed`, never success.

The exit budget starts at group acceptance and includes queueing, journal writes and retries. It is at most sixty seconds, plus bounded owned-process termination. Script/webhook adapter limits still apply on enter. Every action and webhook attempt needs its durable grant before dispatch. Task/project revisions and native approval prerequisites are checked before executable work; the lifecycle rechecks them after exit. Saving pipeline configuration while a project has active or unresolved automations is refused. Task/project deletion, worktree removal and separate completion also refuse active or unresolved work so its owner cannot be orphaned.

`GET /api/tasks/:id/automations` returns the task's retained move receipts. `POST /api/tasks/:id/cancel-automations` with `{"confirm":true}` stops that task's owned work before waiting for task locks. Agent Stop/Pause also revoke its ongoing column work. All routes use the existing local authentication checks. Receipts contain IDs, names, hashes, timings and bounded outcomes, not scripts, webhook credentials, task descriptions or private native history paths. Repeating a recorded transition ID returns its receipt and current task without executing again, even after later moves. Pipeline revision conflicts never trigger the browser’s legacy automatic retry: a new move ID requires a new user action because source effects may already have occurred. There is no automatic move retry or input replay.

Normal shutdown aborts accepted automation moves, stops owned script processes and waits for their durable cancellation. Server shutdown retains its existing bounded grace and native-process cleanup. On first load, Board recovers only a task's referenced unfinished journal, and only when its owning PID is known dead. It preserves confirmed effects and marks unknown work interrupted. Missing/corrupt journals block their task's next cross-column move; unrelated tasks remain usable. A live or uncertain owner cannot be claimed. Recovery never starts a script, sends a webhook or resumes an agent.

State version 6 adds bounded task-scoped move references so older applications cannot reinterpret active actions. Versions 2–5 migrate with an exact original backup; version 5 pipelines, Composer text, Base and native session records are preserved. Portable board backups omit move grants/history and machine sessions. Imported automation definitions remain disabled and require explicit configuration review. No load, import or settings save dispatches actions.

This is the backend runtime step, not completed Kanban parity. The [Column Manager editor and visible receipts](pipeline-automation-editor.md) expose scripts/webhooks/notifications and task-scoped Stop. Explicit retries, immediate/deferred agent delivery and advanced session strategies remain pending. Tests use real script process trees, disposable Git worktrees, local HTTP fixtures, simulated browser alerts and simulated native agents in actual PTYs. They do not establish authenticated live-provider compatibility.
