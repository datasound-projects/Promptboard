# Bulk pipeline restoration

Select archived pipeline rows by checkbox or Select visible, choose a destination, and Restore selected. Clear selection removes all selections. Filtering does not discard already selected rows; the button reports the total selected count. Requests follow selection order through the same column move endpoint as an ordinary restore. Active destinations follow column settings and can start agents/actions; To Do resets the retained context. Composer text, Base delivery and inherited CLI tools use the existing paths.

Before starting, capture each task revision, the board settings revision and a distinct transition ID for each row. The optional integer `expectedProjectRevision` is enforced by both plain and journaled pipeline moves before effects, with the existing asynchronous revision checks retained. Completed exact-ID replays remain idempotent. Legacy callers without the new field keep their current behavior; legacy stages refuse the pipeline-only field. The existing authenticated route explicitly forwards it, and the session advertises `pipelineBulkRestore` so older servers cannot expose bulk controls while ignoring the guard.

Each row keeps a separate outcome: restored, needs review or not started. One refused row does not hide successful restores. A missing/malformed/lost response stays reviewable and never triggers an automatic retry or replacement transition ID. Later observed placement alone does not turn an unknown response into a confirmed outcome. Explicit future requests still use the backend's ownership, revision, cancellation and no-replay checks.

Double activation cannot create another group. Selection and per-row restore controls are disabled during the group. Stop remaining, closing the dialog or changing projects skips requests that have not started; the current request may continue. These controls do not stop an agent or automation already accepted by the server. Use that task's existing Details/Stop controls for its owned work. Results stay scoped to their original project and do not replace another project's UI. Reload loses the browser's batch summary; inspect saved task/move state before retrying uncertain work.

This adds bulk restore to the [completed-task table](pipeline-completed-tasks.md). Bulk deletion, full telemetry/cost/change summaries, expired-context warnings and global archive search remain pending. No new agent input, native permission change, dependency or application restart is introduced.

Verification uses real disposable Board/API/browser fixtures and held/lost responses. It checks stale task and board settings revisions, before-effect rejection for plain/journaled paths, exact-ID replay, old-style API compatibility, legacy refusal, keyboard checkbox/select/clear and header controls, selection order across filtering, repeated activation, both themes and 390/1280 widths, partial success, stop/close/project changes, lost completed replies, older-server capability fallback, exact Composer text and zero native process starts. No live provider or OS alert is used.
