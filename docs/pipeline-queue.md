# Queued destinations and manual columns

A pipeline run that is still waiting in the supervisor's FIFO queue can move to a column with different provider, model, effort, native permissions or Base resources. Acceptance temporarily holds its queue entry in place while validating the destination and atomically updating the queued run, logical-session settings and card placement. No process starts with the old destination settings. Held entries never block the queue: a free slot goes to the first entry that is not held, in FIFO order. Once released, the held entry starts before any entry queued after it that is still waiting. Repeated accepted moves use the latest destination's effective settings. Composer task text and the worktree remain unchanged; the first envelope and Base delivery are prepared for the chosen destination.

Fresh queued conversations can change provider before any CLI starts. A queued native resume can change settings/Base for the same provider without replaying task text; its previously captured native ID remains intact. Switching providers on a queued native resume is refused until the handoff implementation is available. A run that has already left the queue for startup/resource preparation is also refused rather than changing flags beneath its launch; pause it before making that change. [Live same-provider reconfiguration](pipeline-live-settings.md) waits for an observed native turn boundary before resuming the conversation with new settings/Base.

An explicit Stop during acceptance can remove the queue entry. Retargeting never adds it back. Task/project revisions, Base/default-agent settings and the queued run/session state are rechecked before publishing the new destination; failed acceptance leaves the old configuration intact. Imports and settings reads still start nothing. Startup failure uses the accepted transition's normal rollback protection.

Arrival in an active column with auto-start disabled parks an existing queued or live session, preserving its conversation and worktree. It does not archive the card or reset its session as To Do does. The card's explicit Start action can resume captured, unchanged same-provider context; a parked queue entry that never captured a native ID requires a fresh conversation. An explicit start decision on the move overrides parking. Same-column reorder remains inert.

Validation uses simulated CLIs in real PTYs and temporary Git repositories: repeated provider/model/Base changes with FIFO retention, a later run taking a freed slot while destination validation or column actions hold an earlier entry, that entry starting first once released, cancellation during that hold, already-preparing launch protection, and manual parking followed by native resume. Legacy stage behavior and Composer/Base delivery remain in the full regression suite.
