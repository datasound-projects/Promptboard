# Owned initial prompt submission

An initial task envelope that exceeds the adapter's argv limit uses the existing bracketed-paste path. It still supplies the exact persisted prompt and selected Base instruction sections once. This step retains the startup delay, fallback delay and 300 ms paste-to-Enter spacing; it does not alter provider flags, CLI tools/MCP inheritance, Base configuration, task bytes or board schema.

The paste and its delayed Enter now belong to the exact Supervisor session and PTY. Stop, Pause, shutdown, failure, confirmed/ended sessions, uncertain activity, removal or process replacement cannot acquire their bytes. Enter also requires the same input epoch and observed native identity as the paste. Any nonempty human input before the paste consumes the pending automatic paste and clears its startup/fallback timers before writing the human bytes. This applies before the first lifecycle event and after startup has scheduled the paste. Later startup events cannot reacquire the prompt. Human input after the paste cancels its automatic Enter. Both protections include partial drafts and failed human transport writes; empty input and input rejected by the existing size/type checks retain an unchanged pending paste. Main startup also revokes pending submission; subordinate startup does not own it. Timer handles are retained and cleared during teardown.

The initial paste consumes its one attempt before transport. A write exception or Enter exception stays unconfirmed, reports a fixed terminal-check message through existing lifecycle/waiting fields and marks pipeline activity uncertain. Later native Stop events cannot claim task-completion evidence or authorize legacy automatic advancement while that process's initial write remains unknown. It cannot escape a timer callback, leak transport diagnostics, retry a partial write or stop the process as an attempted recovery. Original task and full accepted envelope remain in their existing private artifacts. Human interruption reports that automatic submission was cancelled; it never clears or retypes the draft. No delivery success is inferred from a PTY write.

Read-only native receipt checkpoints are unavailable while initial Enter is pending, and existing tickets cannot confirm across the owned input epoch. This is a narrow initial-input fix, not the native automation scheduler. It does not prove interactive readiness or detect drafts entered outside Supervisor. Those checks remain required before enabling automated continuation messages. After human interruption, check the terminal before explicitly supplying the task; the accepted task and prompt artifact remain unchanged, and no automatic retry or draft clearing occurs.

Four regression scenarios fail on the prior implementation: Enter after a human draft, delayed writes to stopped owners, an uncontained paste exception and a premature receipt checkpoint. Additional tests cover main native identity/startup changes, uncertain/ended owners, replacement, exact one-time submission and an Enter transport exception. A simulated Claude CLI in an actual disposable PTY captures the complete long envelope and confirms it matches `prompt.md` byte-for-byte, with portable Base instructions, native Base MCP delivery and inherited CLI tool flags intact. It uses no signed-in provider or actual MCP process. These fixtures do not establish authenticated live-provider compatibility.

Pre-paste regressions cover both legacy and pipeline sessions, input before/after startup, failed human transport, repeated startup events, and the empty/rejected-input control. The two interruption scenarios fail on the prior implementation; all custody regressions pass on Node 22 and 24.
