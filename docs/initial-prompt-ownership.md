# Owned initial prompt submission

An initial task envelope that exceeds the adapter's argv limit uses the existing bracketed-paste path. It still supplies the exact persisted prompt and selected Base instruction sections once. This step retains the startup delay, fallback delay and 300 ms paste-to-Enter spacing; it does not alter provider flags, CLI tools/MCP inheritance, Base configuration, task bytes or board schema.

The paste and its delayed Enter now belong to the exact Supervisor session and PTY. Stop, Pause, shutdown, failure, confirmed/ended sessions, uncertain activity, removal or process replacement cannot acquire their bytes. Enter also requires the same input epoch and observed native identity as the paste. Any nonempty human input after the paste cancels that automatic Enter before writing the human bytes, including a partial draft or a failed human transport write. Main startup also revokes pending submission; subordinate startup does not own it. Timer handles are retained and cleared during teardown.

The initial paste consumes its one attempt before transport. A write exception or Enter exception stays unconfirmed, reports a fixed terminal-check message through existing lifecycle/waiting fields and marks pipeline activity uncertain. Later native Stop events cannot claim task-completion evidence or authorize legacy automatic advancement while that process's initial write remains unknown. It cannot escape a timer callback, leak transport diagnostics, retry a partial write or stop the process as an attempted recovery. Original task and full accepted envelope remain in their existing private artifacts. Human interruption reports that automatic Enter was cancelled; it never clears or retypes the draft. No delivery success is inferred from a PTY write.

Read-only native receipt checkpoints are unavailable while initial Enter is pending, and existing tickets cannot confirm across the owned input epoch. This is a narrow initial-input fix, not the native automation scheduler. It does not prove interactive readiness or resolve drafts already present before a paste; those checks remain required before enabling automated continuation messages.

Four regression scenarios fail on the prior implementation: Enter after a human draft, delayed writes to stopped owners, an uncontained paste exception and a premature receipt checkpoint. Additional tests cover main native identity/startup changes, uncertain/ended owners, replacement, exact one-time submission and an Enter transport exception. A simulated Claude CLI in an actual disposable PTY captures the complete long envelope and confirms it matches `prompt.md` byte-for-byte, with portable Base instructions, native Base MCP delivery and inherited CLI tool flags intact. It uses no signed-in provider or actual MCP process. These fixtures do not establish authenticated live-provider compatibility.
