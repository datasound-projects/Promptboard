# Import GitHub issues into Backlog

Open a pipeline project's **Backlog**, then choose **Import issues**. Connect an `owner/repository` name or its HTTPS GitHub URL. Promptboard verifies read access using your existing signed-in GitHub CLI before saving a source. It never changes CLI authentication or starts an agent during connection, preview or import.

Choose a saved source and filter the current page by title/issue number, Open/Closed/All status, type, assignee or label. Open and Hide imported are the defaults. These filters are local to the loaded page and do not fetch or mutate tasks. Literal issue titles/descriptions are shown safely, with a link to the original issue. Each preview contains at most 100 raw source rows; pull requests are excluded. Previous/Next page controls expose more source pages, including pages containing only pull requests. Unsupported metadata and the page limit are reported.

Select issues individually or with **Select visible**. Hidden selections remain selected. Import or clear selections before changing sources or pages. An issue title longer than 120 characters requires an explicit short board title; its original title remains in source details. **Import** captures the project, source, page, selected issue identities and metadata revisions. The backend rereads that page and atomically saves the accepted batch. Imported drafts preserve exact descriptions, labels and assignees, start with default priority, and receive no board number or agent session until promotion. Composer tasks retain their exact text and To Do routing.

Imported identities remain known after promotion, archiving, deletion or source reconnection. Disable **Hide imported** to inspect those rows; they cannot be selected again. Backlog, board, completed and task-detail presentation retain an original GitHub issue link. Removing a source defaults to **Keep source** and removes configuration only, preserving drafts and duplicate identities.

Failed source access retains typed repository text. Failed preview refreshes retain the previous page and selections while disabling import until an explicit successful read. Stale or unknown write results retain selections and title overrides, require **Refresh choices**, and never automatically repeat a write. Refresh choices reads saved metadata and removes confirmed imported selections. Closing and Escape are disabled during an accepted write, and switching projects does not change that write's captured owner. Older servers hide the import control and cannot submit hidden actions.

The picker currently previews and filters one explicitly loaded page. [Persistent cached snapshots and explicit incremental synchronization](backlog-source-sync.md) are available. Attachment downloads, GitHub Projects, Azure DevOps and Asana imports remain separate steps. The [import backend](backlog-github-imports.md) describes persistence, limits and atomic deduplication. Kangentic's [Backlog and imports](https://www.kangentic.com/guide/backlog/) defines the target behavior.
