# Column pipeline: main-session checkpoint

Column Manager now offers an explicit switch from the original stage workflow to a column pipeline. Saving confirms the switch; opening settings, reading configuration, and importing a backup never launch work. Existing projects and new projects retain the legacy stage workflow by default while parity implementation continues. Migrated projects receive `workflowMode: "legacy"` explicitly. The legacy stage instructions, review/test gates, merge behavior, and Autopilot remain available on legacy boards.

Pipeline columns use stable IDs and `todo`, `active`, or `done` roles. Display names do not trigger instructions, commits, tests, review acceptance, or merges. Active columns can be renamed, reordered, added, and removed independently; occupied columns cannot be removed. To Do and Done roles remain first and last. Base assignments follow stable IDs across renames and reordering, and assignments to removed IDs are detached.

Composer engineered prompts, edited split tasks, and new cards enter the To Do role without starting an agent. The first authorized arrival at an active column creates the task worktree and queues a run when auto-start is enabled. Manual columns can be started from the card. First input contains the task envelope described in [pipeline prompts](pipeline-prompts.md) plus selected Base text. It adds no stage directives. Native permissions come from the configured column, independent of its display name or ID. Claude and Gemini plan mode use their native modes; Codex uses a read-only sandbox with approval on request. Pipeline sessions inherit user-configured CLI tools/extensions alongside selected Base resources, including native MCPs and supported Claude subagents. The CLI still enforces permissions and administrator policies.

A move between auto-start active columns with the same effective agent configuration and Base selection keeps the same process and logical conversation, whether the agent is busy or waiting. It sends no message and does not confirm the turn. Arrival in a manual column parks the agent unless an explicit start decision is supplied. Reordering a card within its column performs no lifecycle action. Repeated transition IDs return the prior outcome without dispatching another agent. Current live-run metadata records the column where that process was accepted; the card records its current column.

Moving to Done suspends the owned process and archives the task while keeping its logical conversation, native ID, worktree, and artifacts. Restore to an active column starts/resumes according to that column's auto-start setting. A captured, unchanged conversation from the same provider and worktree resumes with no task replay; selected Base text is resent only if its effective definition selection changed. An explicit continuation on Resume is delivered literally. Changed task text starts a fresh conversation on a new arrival; the explicit Resume button refuses to silently substitute a fresh conversation.

Returning to To Do stops the owned agent and resets the task's current session reference. Historical sessions, output, and worktree files are retained at this checkpoint. Leaving To Do subsequently starts a fresh conversation. Automated worktree/branch reset with local-only commit and dirty-file protection is still pending.

Pause agents before editing the pipeline configuration. [Live same-provider settings/Base changes](pipeline-live-settings.md) now wait for native turn completion and settled observations, then resume the exact conversation with the destination settings. A timeout or pre-stop conflict retains the original process/card; explicit Stop/Pause cancels the handoff. [Queued destination changes](pipeline-queue.md) preserve FIFO while accepting the latest settings before startup; already-preparing launches and cross-provider native resumes still require Pause. Provider handoff, isolated session slots and forced fresh-session policies remain pending. [Native approved-plan routing](pipeline-native-plan.md) now uses the configured column/profile target for verified main Claude/Gemini approvals. Compatible routing keeps ongoing native implementation without injecting input; required settings/Base handoffs use the native resume-only continuation. Requests and finished responses do not constitute approval. Codex still requires an explicit move.

Configured script and webhook rows now use the [column automation runtime](pipeline-runtime-automations.md). The [row editor and recorded results](pipeline-automation-editor.md) expose scripts/webhooks and scoped Stop. Native message delivery and notification reception remain pending. Enabled message rows, handoff context, isolated sessions and forced fresh-session strategies remain refused. Named sparse profiles remain valid configuration data; profile/task selection UI is pending. Legacy Autopilot is unavailable on pipeline boards.

The separate [activity observation checkpoint](pipeline-activity.md) tracks outstanding work and native plan approval evidence. Those current observations gate live settings handoffs and verified native approved-plan routing. Column automation messages remain pending.

State version 6 is required so older applications cannot reinterpret pipeline automation ownership. Versions 2–5 migrate with an exact original backup; existing logical sessions and version 5 pipelines are preserved instead of reconstructed. Pipeline board exports use portable backup version 4, while legacy-only exports remain version 3. Imports preserve column structure and pending strategy definitions with auto-start and automation rows disabled, omit machine runs/sessions, and require normal confirmation of repository paths and Base imports. Saving Column Manager explicitly enables the selected supported arrival settings.

Validation includes legacy regression coverage, migration/session preservation, exact Composer input, role IDs distinct from stage IDs, dormant imports, duplicate requests, no hidden delivery actions, compatible live-process continuity, Done suspension/native restoration, To Do reset, Base MCP delivery in Planning/Review, stable Base assignments, and task edits racing startup. Native-provider integration uses simulated CLIs in actual PTYs, not live accounts. Real Chrome checks conversion, editing, reordering, new columns, keyboard activation, both themes, and desktop/phone geometry.
