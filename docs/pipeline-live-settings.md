# Live settings handoff

On an opt-in pipeline board, moving a live agent to an auto-start column with different settings or Base resources can resume the same provider's conversation automatically. The card shows its existing “Moving to…” state in the source column while the request waits. Compatible moves still keep their process immediately. Queued destination changes retain their existing FIFO slot as described in [Queued destinations](pipeline-queue.md).

The handoff waits up to two minutes for the supervisor's current observations to report a native parent turn end, no permission wait or observed outstanding tools/subagents/background/scheduled work, and 1.5 seconds of settled output. Silence alone and a saved activity snapshot never authorize a restart. Unread partial hooks block readiness; malformed or truncated lifecycle records leave observation uncertain until explicit suspension/resumption starts a new tracker. Typing any terminal input invalidates the previous completed turn immediately, including an unfinished prompt that has not produced a native hook yet. The provider's observation coverage remains visible; Codex currently reports turns, not a complete inventory of background work. These checks cannot prove the absence of activity the CLI does not expose.

Before signalling the owned process, Promptboard atomically checks the current task revision and text, source column, project settings, workspace, Base revision, default agent and exact native session ID. It records a system suspension intent, blocks terminal input during that brief lease, drains native events again, then checks both fresh readiness and the latest committed board state. New activity revokes the lease and resumes waiting. A changed task or setting fails the request while retaining the original process. A timeout also keeps the original card/process. Explicit Stop and Pause cancel the handoff, including unresponsive discovery before or after suspension; a Pause that arrives after the system process exits leaves the original conversation paused rather than launching a replacement. Cancellation remains active through replacement acceptance. If the new run’s atomic publication was already in progress, its placement is accepted but the run is paused/stopped before queueing. A late Stop/Pause follows only that same logical conversation, and the UI announces that it did not start.

After the process exits, the destination run uses the captured native ID in the same worktree, applies its model/effort/native permissions, and prepares the selected Base delivery. Original task text is not repeated. Changed Base text is supplied; unchanged Base text is not repeated. The logical session's current configuration follows the accepted resumed run, while historical run settings and artifacts remain intact. Dirty files, branches and Composer text are retained. A startup failure has the normal accepted-move rollback protection and never substitutes a fresh conversation for a failed native resume.

Settings must still match immediately before accepting the replacement run. If they change after the owned process was stopped, the request fails with its original conversation paused and recoverable in the source column. Restarting Promptboard interrupts an unfinished handoff; it never automatically replays the move or relaunches a process. System suspension is distinct from the user's explicit pause intent.

Cross-provider conversation handoff, already-preparing launch changes, isolated/forced-fresh session strategies and automatic native approved-plan routing remain later checkpoints. Native approval can change permissions inside the existing CLI session; the approved-plan routing implementation must preserve that session when no model/effort/Base change requires a handoff. This checkpoint does not automatically route a plan or deliver column automations.

Regression tests use all three simulated providers in real PTYs and disposable repositories. They cover busy tools and background work, partially entered prompts, permission waits, stale saved readiness, new work and edits during pause-intent persistence, explicit Stop/Pause races, exact native resume, destination Base delivery, dirty-file retention and no task replay. These are offline adapter simulations, not authenticated live-provider verification.
