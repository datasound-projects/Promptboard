# Editing column actions and reading results

On an opt-in pipeline board, open Column Manager and choose a column. Its Automations section contains On exit and, for active roles, On enter lists. Add a script, webhook, Notify me action, or deferred Send message to agent row on active-column entry, name it, choose its switch, and move it up/down to set order. Delete affects the draft until Save. Copy creates an independent row with a new ID and unique name in the chosen column/group; it does not share future edits. To Do and Done offer exit groups only. Each group permits forty rows.

Script fields retain literal text and choose a timeout of 1–120 minutes. The runtime selects the verified task worktree or project checkout. On Windows scripts use PowerShell, including explicit `exit $LASTEXITCODE` when a native command's exit code should determine the result. Webhooks choose HTTP method, URL, body and JSON headers. Invalid header drafts stay invalid across reordering; form validation prevents saving or copying invalid headers. Server validation still enforces all bounds and reserved fields. No editor action, copy, settings save or configuration read executes a row.

Saved disabled agent-message definitions remain intact. On servers advertising deferred-message support, active enter rows can be enabled with After the current work finishes delivery. New message rows explicitly use deferred mode. Turning Start an agent here off displays message switches as off and disabled while preserving the saved definition; turning it back on restores eligibility without enabling a previously disabled row. Immediate/exit/slash delivery remains unavailable; saved unsupported definitions are preserved and can be switched off. Older servers keep new message choices unavailable. Notify me offers bounded title/body templates and requires separate [browser permission and reception](pipeline-notifications.md). Saving a notification row never asks for permission or shows an alert. Changing a row's type replaces its type-specific fields deliberately. Stable row and column IDs preserve the existing configuration relationship and Base assignments.

Cards show their current automation phase and expose Stop automations while work is pending/running or blocked, including message delivery after placement completes. Stop targets only the task's owned column work and retains its receipts. Details includes separate automation history: source/destination, placement status, session lifecycle and every row's result, with recorded exit/HTTP codes, separate agent-input delivery status and bounded reasons. A completed placement can contain failed or unconfirmed rows; open its recorded results instead of treating placement as proof that every action succeeded. Refresh only reads history and never retries effects. Explicit Run again remains pending.

The visible Kanban polls board revision every two seconds, discovering moves accepted through native plan routing or another window. Unchanged revisions preserve the DOM and focus; a changed view retains the focused Stop control. Hidden pages do not poll. Network uncertainty says to check the current board before trying again rather than claiming no save occurred. Pipeline revision conflicts retain the backend's no-replay rule.

Composer's exact engineered prompts and edited split tasks still enter To Do without an agent. Selected Base resources and inherited CLI tools use their unchanged delivery path. Existing stage boards keep their editor and stage behavior. Imported executable rows remain disabled until explicitly reviewed and saved.

Verification uses the actual authenticated local server, controlled webhook transport, jsdom and disposable Chrome profiles. Tests cover literal definitions, disabled-message preservation, invalid-header retention, switching/copying/reordering/deletion, no effects on Save, scoped Stop, durable escaped history, keyboard activation, both themes and 1280/390-pixel viewports. Notification tests replace the browser API and show no real OS alerts. No external webhook or live agent is used. Immediate/exit/slash delivery and explicit retries are still required for full parity. Configured deferred enter rows are additionally checked through real owned offline terminals and the separately documented live Codex check.
