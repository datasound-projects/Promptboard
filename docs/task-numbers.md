# Stable project task numbers

Each server-created task has a positive project-local `number`. The project's persistent `nextTaskNumber` increases in the same serialized atomic store update that creates a task. UUIDs still identify tasks for HTTP routing, workspaces, sessions and automation ownership; the display number never substitutes for those identities. Client-supplied numbers are ignored by task creation/edit APIs.

Renaming, moving, reordering, archiving and restoring retain a number. Duplicates receive a new number. Deleting a task never reduces the counter, including after restart or portable backup/import. Projects allocate independently starting at 1. A rejected or failed write consumes no number; exhaustion refuses creation instead of rounding or recycling an identity. Composer and edited split tasks still arrive in To Do with exact prompt bytes and no agent launch.

State version 7 migrates versions 2–6, assigning previously unnumbered tasks once in their saved array order (including completed tasks). The atomic migration preserves the exact original file in a pre-migration backup and keeps task revisions, content, Base bindings, workspaces, sessions, run records and automation history. Existing numbered identities are validated and retained. Unknown newer state versions remain refused. Optional absent fields in hand-authored current-version records are allocated when a task is next added to that project; this compatibility path does not renumber existing identities.

Portable exports now use `promptboard-backup` version 6 for both legacy and pipeline projects. Numbers and the next counter are required, validated and preserved; duplicate numbers, malformed integers, missing fields and a counter at/below a saved number fail before replacing state. Versions 1–5 remain importable and receive numbers in saved order. Browser-board migration allocates only previously unseen UUIDs into the destination project's counter and remains idempotent. Import still disables executable pipeline settings and carries no machine-specific session/process/workspace grants. Older applications reject version 6 instead of silently losing the deletion counter.

The board/task API and portable backups expose numbers. Cards, completed cards, the pipeline archive, edit metadata and details now display a separate number badge or metadata prefix without changing titles. Archive lookup treats a whole `#digits` query as an exact number; other queries retain literal title filtering. Missing or malformed older-server metadata shows no invented positional number. Completed-card delete cancellation uses saved identity rather than reading a visual badge. It does not add task-number template substitutions or change native prompts, CLI tools, permissions, provider delivery or the running application.

Browser checks use real Chrome keyboard actions in both themes at 1280 and 390 pixels, including the largest allocated safe integer, deleted-number gaps, edit/details inspection, exact archive lookup, literal malicious-looking titles, restoration and older/malformed responses. They verify no agent launches, preserve stored Composer prompt bytes and inspect screenshots.
