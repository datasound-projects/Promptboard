# Deferred enter-message scheduler

`NativeMessageScheduler` connects durable enter-message handoff, [exact target custody](native-message-target.md), queued startup and the [journal-backed input bridge](native-message-dispatch.md). Board moves and the Column Manager now support enabled deferred Send message to agent rows on entry to active columns. The HTTP session capability advertises `pipelineDeferredMessages`; older servers keep those editor choices unavailable. Immediate/busy input, slash commands and exit-message execution remain pending. This is partial parity with Kangentic: its default immediate mode and capped-wait fallback are not implemented. The editor creates an explicit deferred row; saved immediate rows are preserved but cannot run.

The caller supplies an explicit current process-run ID, the frozen rendering task/project revisions and an already started enter action. The coordinator passes those revisions from its immutable metadata snapshot. Preparation checks them before queueing and again before acknowledging handoff, so an old rendered message cannot capture newer card state. After accepted handoff, compatible active-column moves retain the captured conversation. Selection checks the exact project/task/conversation/workspace/configuration snapshot. The recorded move must belong to this application process, have a successful session lifecycle and be entering the task's current active column. The action must match the current enabled deferred message row's recorded configuration hash. Unsupported literal input, slash commands, controls and immediate delivery cannot create a queue.

Scheduling persists one exact message hash/provider/session/run/mode intent and rereads the acknowledged queued receipt before returning the handoff. That response means scheduling, not input or successful work. A coordinator can then continue later enter rows and complete placement while delivery remains queued. Original task text, Base definitions, CLI flags, tools and native permissions remain unchanged.

The scheduler waits for that same queued run to enter its live state; it never starts, resumes or selects a replacement process. It then uses the existing owned transport, which independently waits for completed main activity, native identity/history, bracketed-paste readiness and an untouched human draft. Startup, queue waiting, target rechecks, journal grants and native delivery share one budget of at most 150 seconds. A deadline or cancellation stops late callbacks from reviving delivery.

Invocation FIFO is reserved before asynchronous preparation for each captured run. A cancelled later message cannot erase an earlier live tail. Different run IDs have separate queues. Duplicate identical handoffs share one owner; changed requests cannot replace its message. At most 1,000 active or uncertain owners can be admitted. Known finished jobs release that capacity and enter a separate cache of the latest 1,000 completions, preserving recent handoff/wait identity. Evicting an old completion never grants replay: its durable action is no longer running and cannot schedule another delivery. Unacknowledged outcomes remain owners and retain their blocked-run barriers; they are never evicted into the completion cache.

An explicitly rejected scheduling save grants no ownership and cannot cancel another scheduler's queue. A lost save acknowledgement retains blocked uncertainty, without input or cancellation of potentially foreign intent. After acknowledged ownership, cancellation or changed targets can atomically finish only a still-queued delivery. A competing dispatch grant or lost final acknowledgement blocks further scheduling for that run. Cleanup has a separate bounded 1.5-second save allowance. No path replays input, clears a draft, retargets a message or restarts an agent.

`cancel` targets one owned action. `shutdown` prevents new handoffs, cancels owned requests, awaits their bounded outcomes and shuts down its own dispatcher. The scheduler does not signal native processes itself; the application still owns their lifecycle. Native confirmation remains input evidence only; completion requires independent lifecycle events.

Tests use real journals/coordinator callbacks, simulated owned transport and an actual owned PTY with an offline CLI. The PTY fixture tests both the private adapter and a real configured Board transition, retaining the same process through Code Review. Immediate rows remain refused. Exact Composer text, Base delivery, inherited CLI flags and native receipts remain verified. They cover nonblocking placement, literal template rendering, queued activation, matching configuration, duplicate requests, FIFO cancellation, changed content/settings, hanging preparation, lost/competing acknowledgements, blocked queues and shutdown. They do not certify broad live provider startup, native-resume input or busy queues.


Board integration publishes a machine-owned pending-move reference before scheduling can grant input. State version 8 preserves version 7 task numbers, sessions, Base and extensions with an exact original backup; older readers reject the newer version. Pending references stay separate from the 100-move history window and are omitted from portable backups. A dead-owner pending delivery is marked interrupted on startup, even when placement was complete; it is never replayed.

Placement and message delivery have separate outcomes. Details displays the journal delivery status, and Stop remains available while a completed move has pending messages. Stop cancels owned message requests without stopping the agent. Moving to To Do or Done, editing task content, and application shutdown cancel and await outstanding delivery before publishing changed content or stopping/suspending the process. Compatible active moves preserve invocation order. The first move out of Done skips messages while retaining other enter actions. Manual columns without an agent skip messages.

Known cancelled or terminal receipts release their pending references. Unknown acknowledgements retain blocked ownership: Stop does not erase uncertainty or retry input. A missing or corrupt referenced journal stays unresolved and blocks configuration/deletion; restart does not invent a replacement receipt. Explicit reconciliation and retry controls remain pending. Confirmed delivery means exact native input and a durable receipt, not completion of the requested review, test or merge.
