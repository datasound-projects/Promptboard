# Private deferred enter-message scheduler

`NativeMessageScheduler` connects durable enter-message handoff, [exact target custody](native-message-target.md), queued startup and the [journal-backed input bridge](native-message-dispatch.md). It is private: Board moves, HTTP actions and the Column Manager do not use it yet. Enabled column-message rows remain refused. Immediate/busy input, exit-message execution and activation in the application remain pending.

The caller supplies an explicit current process-run ID, the frozen rendering task/project revisions and an already started enter action. The coordinator passes those revisions from its immutable metadata snapshot. Preparation checks them before queueing and again before acknowledging handoff, so an old rendered message cannot capture newer card state. After accepted handoff, compatible active-column moves retain the captured conversation. Selection checks the exact project/task/conversation/workspace/configuration snapshot. The recorded move must belong to this application process, have a successful session lifecycle and be entering the task's current active column. The action must match the current enabled deferred message row's recorded configuration hash. Unsupported literal input, slash commands, controls and immediate delivery cannot create a queue.

Scheduling persists one exact message hash/provider/session/run/mode intent and rereads the acknowledged queued receipt before returning the handoff. That response means scheduling, not input or successful work. A coordinator can then continue later enter rows and complete placement while delivery remains queued. Original task text, Base definitions, CLI flags, tools and native permissions remain unchanged.

The scheduler waits for that same queued run to enter its live state; it never starts, resumes or selects a replacement process. It then uses the existing owned transport, which independently waits for completed main activity, native identity/history, bracketed-paste readiness and an untouched human draft. Startup, queue waiting, target rechecks, journal grants and native delivery share one budget of at most 150 seconds. A deadline or cancellation stops late callbacks from reviving delivery.

Invocation FIFO is reserved before asynchronous preparation for each captured run. A cancelled later message cannot erase an earlier live tail. Different run IDs have separate queues. Duplicate identical handoffs share one owner; changed requests cannot replace its message. The bounded registry retains at most 1,000 owners and refuses further handoffs at capacity rather than forgetting a consumed action.

An explicitly rejected scheduling save grants no ownership and cannot cancel another scheduler's queue. A lost save acknowledgement retains blocked uncertainty, without input or cancellation of potentially foreign intent. After acknowledged ownership, cancellation or changed targets can atomically finish only a still-queued delivery. A competing dispatch grant or lost final acknowledgement blocks further scheduling for that run. Cleanup has a separate bounded 1.5-second save allowance. No path replays input, clears a draft, retargets a message or restarts an agent.

`cancel` targets one owned action. `shutdown` prevents new handoffs, cancels owned requests, awaits their bounded outcomes and shuts down its own dispatcher. The scheduler does not signal native processes itself; the application still owns their lifecycle. Native confirmation remains input evidence only; completion requires independent lifecycle events.

Tests use real journals/coordinator callbacks, simulated owned transport and an actual owned PTY with an offline CLI. The PTY fixture adds a row only to a private state adapter; the actual Board configuration remains unchanged and its enabled-row refusal is still asserted. Exact Composer text, Base delivery, inherited CLI flags and native receipts remain verified. They cover nonblocking placement, literal template rendering, queued activation, matching configuration, duplicate requests, FIFO cancellation, changed content/settings, hanging preparation, lost/competing acknowledgements, blocked queues and shutdown. They do not certify live startup, native resume, busy queues or application activation.
