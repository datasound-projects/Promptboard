# Journal-backed deferred delivery

`NativeMessageDispatch` privately connects a version 2 queued receipt to `Supervisor.sendNativeMessage`. It is not connected to board moves or an HTTP action. Enabled message rows, provider readiness verification, fresh/resumed session activation and live column scheduling remain pending. Composer, Base, CLI flags and the existing process-start queue are unchanged.

The caller supplies the recorded key/action, literal message and exact provider/logical-session/run/mode/hash tuple, plus a cancellation-aware task/configuration preflight. The bridge rereads the queued intent, requires the current application owner and exact scope, and acquires the journal's one dispatch grant before calling the owned Supervisor. Native input still requires its own history checkpoint and readiness checks. The native grant callback rechecks both preflight and the exact persisted dispatch. Submission and queue acceptance each require strict durable acknowledgement.

Native confirmation now has an optional private `confirmDelivery` callback. The bridge saves the confirmed receipt through this callback while the Supervisor still owns input and hides readiness. A failed, lost or cancelled confirmation acknowledgement keeps process input uncertain and blocks completion/plan routing. A returned success claim without the required callbacks cannot fabricate durable native confirmation. A stored confirmation whose return acknowledgement was lost remains stored; the bridge does not overwrite it or promote the unknown call to success.

Messages supplied to this bridge preserve invocation order per exact process-run scope. Different runs can proceed independently. Cancelled or invalid later requests cannot erase an earlier live queue tail. Duplicate or terminal requests supply no further input. Unknown outcomes retain a blocked owner and queue barrier rather than allowing another send. The bounded registry refuses new requests at 1000 owners. There is no automatic retry, replay, restart, retargeting or queue-barrier clearance.

Preparation, queue waiting, preflight, grants and native input share a maximum 150-second budget. The bridge waits for its owned Supervisor's bounded return when cancellation stops input, rather than releasing an active writer on a promise race. Known outcome publication has a bounded 1.5-second cleanup allowance independent of the cancelled delivery signal. Late save acknowledgements cannot restore success. Queued cancellation uses an atomic queued-only journal operation; it cannot cancel another dispatcher after a competing grant. Cancellation before the queued identity is established, or an unknown save, retains a blocked outcome for explicit reconciliation. Shutdown cancels owned requests and observes their returns; it does not signal another process or undo native work already accepted by a CLI.

Tests use actual journal files, controlled transport callbacks and the existing offline owned PTY. They cover exact scope, callback ordering, forged success, invocation FIFO, queued cancellation, competing grants, lost final acknowledgement and shutdown. The PTY test delivers two literal Unicode messages through journal dispatch/submission/confirmation stages while preserving original Composer/Base input and inherited CLI flags. Native-input tests also verify failed/hanging confirmation saves and sticky uncertainty. No signed-in provider or quota is used. These checks do not certify live provider readiness or queue behavior.
