# Board profiles and task agent choices

Opt-in column pipelines support named sparse profiles in Column Manager. Default edits the shared board. New creates an inherited ladder; Duplicate copies only that profile's strategy, Rename retains its stable ID, and Delete returns its tasks to Default when the board is saved. Named profiles lock column names, descriptions, colours, ordering, deletion, automations and Base assignments. Those remain shared and are edited under Default.

Each supported strategy field has Inherit column, Use default and Override choices. Inherit leaves the field absent, Default stores null, and Override stores its value. The editor supports auto-start, provider, model, effort, permissions and native plan target. Existing advanced definitions are preserved, but isolated/fresh sessions and context handoff still cannot be enabled. Empty profile-column entries are omitted. Removing a column under Default prunes its profile entries and plan targets.

New/Edit card and Task details offer mutually exclusive Column settings and Agent override choices. Column settings select Default or a named board profile; the dropdown is disabled when none exist. An override requires a native provider and replaces the whole agent/model/effort/permission tuple across columns; empty optional pins use that agent's defaults. Changing provider clears the other override pins. The task's choice and effective next agent are shown on its card. Base agent profiles and board workflow profiles are separate concepts: selected Base resources and inherited CLI tools still follow the actual run's provider and permissions.

Saving is inert. Task settings use the task start lock, exact card/project revisions and pure adapter validation across active columns. Active/queued agents and unresolved column automations block a changed choice. No CLI discovery, MCP connection, workspace creation, process signal, terminal input or automation dispatch occurs on save. Board profile edits keep the existing project-wide pause requirement; they do not propagate live. Historical runs, sessions, workspaces, plan text and task content revisions stay intact. Later explicit moves or Start resolve the saved choice through the existing lifecycle. Native provider changes and other unsupported lifecycle operations retain their existing guards.

Composer Add to Kanban and edited Task Split keep their existing Default selection and exact prompt bytes, entering To Do without a run. A card copy retains its profile or whole-task pins and Base selections, enters To Do and owns no copied worktree/session. Metadata-only selection changes do not alter the original prompt, source, content revision or generation checks. Editing text still invalidates its earlier checks normally. Stale drafts remain visible for review; the browser never retries a save with a newer revision automatically.

Portable exports now use version 6, preserving both task selections and [stable task numbers](task-numbers.md). Versions 1–5 still import; a version 4 pipeline defaults its task choices. Unknown, conflicting or unsafe profile/pin references fail before replacing state. Import keeps original profile definitions pending, disables arrival starts in both default/profile layers and all automation rows, and excludes machine runs, sessions and ownership grants. Subsequent export retains pending original definitions and choices. Older applications reject version 6 instead of silently dropping the deletion counter. Local board state is version 7.

Validated offline: strict choices, inherited/cleared/set fields, guarded saves, exact Composer/CRLF/Unicode text, provider/Base resolution on explicit Start, stable rename and deletion, duplication, version 4/5 imports, token/origin checks, stale drafts and keyboard layout in both themes at desktop/narrow widths. Tests use disposable repositories, simulated execution and owned browsers; they do not claim signed-in provider compatibility.

Repository-shared `promptboard.json` and personal overrides now have an [explicit reviewed application](pipeline-repository-configuration.md). Automatic synchronization, retained ghost columns, live profile propagation and agent-facing profile/task tools remain pending. Native message automations and advanced session strategies are separate remaining steps. The reference behavior is described in [Kangentic's board profiles documentation](https://www.kangentic.com/features/board-profiles/); this checkpoint does not claim completed parity.
