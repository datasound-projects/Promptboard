# Native agent message receipts

`NativeMessageReceipts` prepares read-only evidence for automation message delivery. It checks the CLI's structured conversation file after a private checkpoint taken before submission. It does not type into a terminal, start an agent, retry input or advance a card. Board, supervisor and HTTP integration remain pending; enabled automation rows are still unavailable. Composer, Base delivery and inherited CLI tools are unchanged.

A reader belongs to one provider, native conversation and process run. Its adapter supplies an absolute verified history path and an input epoch reader. The epoch must increase on every user terminal write, including partial input, and become unavailable when the run stops or its identity changes. The integration must close the reader on teardown and cancel each checkpoint when its delivery is cancelled. These calls also revoke an in-flight check. A checkpoint is opaque, cannot be recreated from serialized data, belongs to its reader and is bound to one exact transport text. One confirmed checkpoint cannot grant another receipt. Its lifetime is at most 150 seconds and can be shortened for the delivery budget.

JSONL checkpoints retain a byte offset, physical file identity and a hash of the entire captured prefix, without retaining raw history text. Only later complete records can match. Replacing, truncating or changing that prefix invalidates the checkpoint even if another identical prompt appears in the file. Timestamps do not authorize receipts, so an earlier identical message or skewed clock cannot confirm a new submission. Matching preserves every byte of the expected UTF-8 text, including whitespace; substring or trimmed matches are insufficient. The scheduler must pass the actual transport text when an adapter wraps literal input.

The supported record shapes are main Claude user messages, Codex user response items and user-message events, Gemini append-only user records, and legacy Gemini conversation JSON. Claude sidechains, metadata, tool results, assistant output and local command records cannot confirm plain input. Codex checks the rollout's thread ID rather than a fork's root session ID and requires a CLI source when one is specified. Gemini requires the exact native session ID and a main conversation when kind is specified. New Gemini messages need IDs absent from the baseline; rewinds, removed messages, altered matching content or duplicate new IDs invalidate evidence. Legacy Gemini files may be atomically replaced by the CLI, but the native ID and hashes of all prior messages must remain unchanged. Changes to earlier messages therefore produce uncertainty rather than a false receipt.

Claude's native queue entry returns `accepted`, distinct from a `confirmed` conversation user turn. It does not consume the checkpoint; the caller can continue checking for the eventual user turn. Removing queued input revokes queue acceptance. Neither result proves that an agent completed the requested work. The forthcoming scheduler and durable asynchronous receipts must preserve these distinctions and must not automatically repeat input after an unknown outcome. The coordinator's current `confirmed: true` callback contract is not connected to this reader yet.

Readers are bounded to 16 MiB per file, 1 MiB per JSONL record, 100,000 records and 256 KiB of expected input. Symlink files and nonregular files are refused. Torn appends or legacy writes remain pending until complete; malformed complete JSONL records, changed identities and exceeded limits fail closed. Missing paths, unsupported slash commands and control characters cannot claim success. A scheduler must bound polling and surface unavailable or unsupported evidence; it must not infer confirmation from PTY echo, quiet output or launch flags. Plain slash commands need a separate verified command adapter before they can be enabled.

These are observational receipts from files owned by the provider CLI, not an authorization mechanism or authentication of an arbitrary file. The caller must verify history provenance and current task/run ownership. Receipts must never authorize native plan approval, permission changes, destructive cleanup or merging. Results contain fixed status/reason codes, without paths, prompt text or native conversation IDs, and the module writes no artifacts. Private tickets are discarded with their owning reader; the journal integration will persist bounded delivery outcomes rather than raw conversation content.

Tests use disposable native-format files and simulated input epochs. They cover exact new turns across all formats, old identical prompts, skewed timestamps, queue acceptance/removal, main versus subordinate records, patches and rewinds, file rewrites/replacement, partial UTF-8, unknown shapes, bounds, expiry, cancellation during reads, concurrent verification and opaque-ticket ownership. This verifies the reader contract and fixture formats; no live provider session has been exercised by these tests.

Format evidence comes from [Claude hook transcript fields](https://code.claude.com/docs/en/hooks), [official Codex rollout serialization](https://github.com/openai/codex/blob/b741e480e203f037ca726bc2a76d99a8e8668e66/codex-rs/history/src/rollout_payload.rs), [Codex user-message protocol](https://github.com/openai/codex/blob/b741e480e203f037ca726bc2a76d99a8e8668e66/codex-rs/protocol/src/protocol.rs), and [Gemini recording types](https://github.com/google-gemini/gemini-cli/blob/fb972b2f87fe7d5b06d37eac711490162d98de2c/packages/core/src/services/chatRecordingTypes.ts) and [recording implementation](https://github.com/google-gemini/gemini-cli/blob/fb972b2f87fe7d5b06d37eac711490162d98de2c/packages/core/src/services/chatRecordingService.ts). Claude user/queue shapes were compared with the current Kangentic verifier; its timestamp/trim matching and retry behavior are not used here. Provider formats can evolve; an unknown shape remains unconfirmed until its adapter is verified.
