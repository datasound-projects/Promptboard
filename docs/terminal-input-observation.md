# Private terminal input observations

Owned pipeline processes now keep a separate in-memory observation of bracketed-paste mode, incomplete terminal controls, manual input and closure. The existing PTY output handler feeds it before streaming/logging; every accepted nonempty manual input marks it before transport, including failed writes. Empty/rejected input stays inert. Automatic terminal reports and mouse reports (a click, wheel or motion over a CLI that tracks the mouse, as Claude Code does) type nothing: they reach the CLI, are held back during a native paste, and never count as manual input. A key that answers a dialog the CLI reports through a permission hook is not manual input either; Codex reports no dialogs, so keys answering its questions do count. Stop/owned kill and actual exit close the observation. A native resume creates a fresh observation for its new process rather than inheriting the old terminal's draft state.

The observer recognizes complete DECSET/DECRST 2004 controls across output chunks, grouped numeric parameters, C1 forms and hard/soft resets. It bounds control metadata to 64 characters and 32 parameters. Ordinary title/string metadata blocks a pending control until its terminator without discarding an unchanged mode. Embedded ambiguous controls, unsupported mode syntax and oversized controls lose affirmative mode evidence. Opaque payloads cannot establish a mode and are never retained. Ordinary output does not manufacture mode evidence. These are conservative observations rather than a complete VT emulator.

Only fixed metadata lives on the Supervisor process session. It is absent from Board state, HTTP run updates, backups and browser capabilities. This adds no second transcript, credential access, dependency, provider flag, permission change, input, draft clearing, interruption or restart. Composer task bytes, Base delivery and inherited CLI tools follow their existing paths.

A mode observation is **not readiness or a dispatch grant**. `controlPending` must be checked alongside the mode, and manual input remains observed for that process even after Enter, output or a main-session startup event. The forthcoming scheduler still needs authoritative lifecycle/waiting evidence, owned input sequencing, exact native identity/configuration, durable no-replay dispatch, cancellation and new native-turn confirmation. It must not use these fields alone to send input. Native continuation delivery and enabled message rows remain pending.

Tests cover every split point of enable/disable controls, ordered mode changes, grouped/zero-padded parameters, ordinary/opaque metadata, string terminators, C0/C1 controls, reset, malformed/oversized controls, private metadata and terminal closure. The Supervisor input-before-failure and actual PTY integration regressions fail on the prior implementation. Disposable simulated Claude/Gemini/Codex PTYs cover actual output callbacks, empty/manual input, HTTP metadata exclusion, Done closure and native-resume isolation. No authenticated provider is exercised.

The reset and parameter bounds follow the application's pinned xterm 6.0.0 [input handler](https://github.com/xtermjs/xterm.js/blob/6.0.0/src/common/InputHandler.ts) and [parameter parser](https://github.com/xtermjs/xterm.js/blob/6.0.0/src/common/parser/Params.ts). The observation is implemented locally and adds no runtime parser dependency.
