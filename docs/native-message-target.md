# Private message target custody

`captureNativeMessageTarget` captures one pipeline task's project, logical conversation and process run from a Board state snapshot. It starts no agent, reads no history, writes no terminal input and provides no readiness or permission grant. It is a private building block for the forthcoming column scheduler. Enabled column message rows remain unavailable.

Selection requires an active column, one unique live run, matching project/task/session links, the session's current run, matching provider/configuration and exact task/session/run workspace and branch. Queued, running and permission-waiting runs can be selected; their ability to receive input is decided separately by the owned native transport. Imported unreviewed configurations, archive/reset, pause intent, exited processes, ambiguous identities and malformed metadata supply no target.

The private recheck binds task content and content revision, project revision, run configuration and pinned Base definitions, task profile/agent/Base selections, Base revision and application settings. Any change invalidates the captured request instead of selecting a replacement. The Base/settings checks are conservative: even an unrelated saved change requires a new request. A compatible move between active columns, task ordering and ordinary lifecycle polling retain the same conversation without depending on stage names or the task's move revision. Normal resource preparation/supply metadata does not change pinned Base identity. Native identity may become known after queueing; once observed, it cannot disappear or change.

Captured prompt/configuration facts are reduced to a hash in a private closure. Only provider, logical session ID and run ID are serializable; native identity, prompt text, workspace and the fingerprint are not exposed or journaled. This is application-state custody, not filesystem verification or a claim of live provider readiness. Native transport still performs its independent exact process, terminal, lifecycle, history and durable-input checks.

The disposable native-message smoke harness uses this recheck before journal dispatch and again before the native input grant. Offline tests exercise actual journal/bridge callbacks, including a compatible move, a replacement after placement and an edit between dispatch and grant. They also verify all providers, queued-to-live identity observation, Base/configuration revocation, ambiguous records and privacy. Actual column scheduling, busy/immediate input and delivery UI remain pending.
