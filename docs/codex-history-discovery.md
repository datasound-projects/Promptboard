# Codex history discovery

Codex resume keeps a conversation's original rollout date. Looking only at the new process's start date and today can therefore miss a valid older history. Usage collection and read-only Supervisor receipt custody now use a bounded exact-thread locator. This change does not start/resume agents, type messages, answer permissions, change CLI settings or alter board state. Composer, selected Base resources and inherited tools retain their existing paths.

The locator resolves the configured Codex home and visits only `sessions/YYYY/MM/DD`. Date folders and native filename timestamps must be valid. It checks the process start date and today first, then the remaining canonical date folders; final selection requires the bounded search to complete with one exact candidate. It never scans archives, credentials or arbitrary directory trees. Symlink session folders, descendant folders and files are refused. A regular file must have a complete valid UTF-8 first JSONL record, at most 1 MiB, with `type: session_meta` and the exact observed thread ID. If `source` is present it must be `cli`; older metadata without that field remains compatible. Related/fork-parent IDs, filename resemblance and modification times are insufficient.

Each lookup enumerates at most 2,048 directories and 30,000 directory entries, including unrelated names. At most two bounded metadata prefixes need reading: another exact candidate already establishes ambiguity. Exhausted or unavailable I/O does not publish a partial match. Missing, malformed, oversized, non-CLI, ambiguous, reverted or compressed histories remain unavailable. No nearer or newer conversation is substituted. The Codex recorder can preserve a thread ID across multiple immutable rollouts after revert; selecting the active one needs an authoritative native locator and remains pending.

The resulting path stays in the owned process's private usage/receipt reader. The strict native receipt reader independently validates identity, file content and checkpoints before confirming any message. This lookup is observational evidence, not a terminal-write grant. It neither retries messages nor approves plans, cleanup or merging. Full conversation viewing/indexing and persisted verified native locations are later work.

Offline tests use disposable homes and native-format metadata. They reproduce missed older dates and filename-only acceptance, then cover exact older/current threads, absent legacy source, unrelated/parent identity, duplicate and reverted rollouts, compressed shadows, malformed/torn/oversized/invalid-UTF-8 records, symlink files/folders, invalid dates, and exhausted search budgets. A controlled Supervisor test confirms a new message from an older native history without terminal writes or path exposure. Simulated native usage fixtures now include Codex's metadata header; no authenticated live CLI is exercised.

Format evidence: [official Codex recorder](https://github.com/openai/codex/blob/b741e480e203f037ca726bc2a76d99a8e8668e66/codex-rs/rollout/src/recorder.rs), [native rollout filenames and revert IDs](https://github.com/openai/codex/blob/b741e480e203f037ca726bc2a76d99a8e8668e66/codex-rs/rollout/src/rollout_file_name.rs), and the independent [receipt format references](native-message-receipts.md).
