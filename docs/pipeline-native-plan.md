# Native approved-plan routing

On an opt-in pipeline board, Column Manager's **After native plan approval** chooses another active column or **Stay in this column**. Planning defaults to Executing. A task's sparse board profile can override that target. The target is resolved from the card's current column when the approval is accepted. Native approval remains a user decision in the agent terminal.

Claude requires a successful main `PostToolUse` for `ExitPlanMode`. Gemini requires an `AfterTool` result for `exit_plan_mode` explicitly reporting approval without an error. A request, rejected/invalid plan, subordinate tool or finished response never approves a plan. Gemini cancellation can have no error field. Codex's current integration exposes no verified native plan-approval event and requires an explicit move. Hook logs retain approval metadata, without plan paths or raw tool results. Successful native re-entry or a new exit request supersedes the prior approval; duplicate identified Claude completions cannot rearm it.

An approval moves the card through the shared pipeline transition path. Compatible live moves keep the process and logical conversation immediately, even while the CLI implements its approved plan. They send no extra input. Permission-only moves retain the CLI's current native permission choice; launch flags remain historical metadata. Empty destination model/effort settings preserve live settings. Concrete model/effort or Base changes use the existing bounded [turn-boundary handoff](pipeline-live-settings.md). Only that native resume receives `Proceed with implementing the approved plan.` as a continuation, without replaying task text. Cross-provider handoff is refused. Manual target columns park the conversation according to their existing arrival rules. Enabled column automations remain unavailable at this checkpoint.

Each approval gets one persisted route attempt before a move can act. Observation persistence is retried before accepting approval. A pending card shows its destination; failed/interrupted routes show a bounded reason. Stop, Pause and shutdown cancel routing, including the window before boundary registration. Task/board changes, a stopped or replaced run, or a superseding native plan invalidate pending acceptance. Failed and uncertain outcomes require an explicit move; duplicate events never retry them. Restart marks durable pending attempts interrupted without launching agents, including attempts attached to already-ended runs. Each run retains at most 50 attempts.

Validation uses simulated Claude/Gemini/Codex CLIs in real PTYs and disposable repositories. It checks continuing implementation, exact native resume, profiles, re-entry, rejection, duplicate signals, persistence failures, cancellation, stale tasks and recovery. Chrome checks keyboard editing and pending/failure display in both themes at desktop and phone widths. Authenticated provider sessions have not been exercised by these offline tests.

References: [Kangentic workflows](https://www.kangentic.com/features/workflows/), [Claude hook events](https://code.claude.com/docs/en/hooks), [Gemini hook events](https://geminicli.com/docs/hooks/reference/), and Gemini's native [exit](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/tools/exit-plan-mode.ts) and [entry](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/tools/enter-plan-mode.ts) tool implementations. Runtime routing follows the reference implementation's resume-only continuation behavior.
